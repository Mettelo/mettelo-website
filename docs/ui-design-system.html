Shared UI foundations

The public website, member experience and administration share tokens and interaction conventions. Keep feature-specific layouts and the existing Mettelo identity. This is a refinement of the current platform, with no changes to admission, authentication, permissions or billing.

Visual standards

AreaConvention
BrandNavy #141824, warm paper #fcfaf5, sand #f7efdd, gold accent #c6892a. Use the darker gold text token on light surfaces. Retain editorial artwork and official identity marks.
TypographyBody and controls use the system Segoe UI/Arial family. Georgia is the editorial display variant; the mono token is for technical references. Body text uses 1.65 line height. Standard controls and secondary text use 14px; captions and helper text use 13px. Mobile form controls use 16px.
SpacingUse the shared 4, 8, 12, 16, 20, 24, 32, 48, 64 and 80px spacing scale. Preserve deliberate reading widths and dense operational layouts.
ShapeStandard controls: 8px radius. Base cards: 16px. Dialog foundation: 20px. Badges: 6px. Fully round avatars and selection chips are deliberate exceptions, not defaults for every action.
ControlsStandard action height: 44px minimum, with a 48px comfortable form variant. Use clear verbs and consistent padding. A text label normally needs no trailing arrow.
StatesPrimary actions use navy/white; gold remains the intentional primary accent on the dark public hero. Secondary actions are outlined; tertiary actions use text. Destructive actions use the danger token and the existing confirmation/reason safeguards. Disabled actions stay visibly disabled.

Use the existing control conventions

Public controls use .btn. App controls use .button, with existing .lxButton, .lwButton, .pcButton, .newsButton and .mpi3Button adapters. The shared stylesheet aligns their base dimensions and variants. Do not introduce another button library to replace working controls.

Keep fields labelled with real labels. Connect helper/error descriptions where relevant. Use native required-field validation and announce asynchronous results. Preserve inputs after errors and prevent duplicate submissions while saving.

Icon conventions

Lucide is the single general UI icon family. The subset is generated from the pinned lucide-react dependency by node scripts/sync-ui-icons.mjs. Commit both snapshots and retain the accompanying ISC licence. Public builds consume the committed subset and need no icon CDN or font request.

ContextUse
Size and stroke20px default/navigation; 18px in compact actions; 16px inline; 24px for larger status illustrations. Stroke 1.75, round caps and joins, current text colour.

LabelsAppIcon is decorative and excluded from the accessibility tree. Give the enclosing icon-only control an accessible name. Never replace a useful action label with an unexplained icon.
ExceptionsKeep official Google/GitHub identities and Mettelo brand illustrations. Preserve meaningful notation and user content, including the CSF 1.1→2.0 crosswalk reference.

Interaction and accessibility

  • Use a visible 3px focus indicator, with a contrasting light indicator on dark navigation.
  • Use native dialogs for modal focus containment and return focus on dismissal. Honour existing busy-state and unsaved-change safeguards.
  • Profile feedback distinguishes unchanged, unsaved, saving, saved, failed and stale records. Restoring the original value clears the unsaved warning.
  • Scrollable administrative tables have a named, keyboard-focusable region. Preserve filters and pagination when opening and closing details.
  • Allow long menu descriptions to wrap. Avoid page-level horizontal overflow; contained table or tab scrolling is intentional.
  • Respect reduced motion. Keep community and discovery available at the configured Lab participation limit.

Verification

Run the existing app tests, typecheck, production build, public build and packaging checks. scripts/check-ui-foundations.mjs verifies public/app parity, safe icon markup and the base contrast pairs. scripts/audit-ui.mjs --output=... inventories routes, components, styles and symbol candidates. Record visual coverage separately from automated source coverage; a passing compilation is not a full accessibility or visual certification.
