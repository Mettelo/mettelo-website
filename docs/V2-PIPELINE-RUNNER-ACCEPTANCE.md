# Runner failure and source-check acceptance — 2 November 2026

Preparation is now separate from publication. prepareWebsiteOpportunityBatch discovers and classifies into a stable {runId,candidates,sourceStats} payload. runWebsiteOpportunityPipeline accepts that prepared payload rather than fetching a different set of listings during a retry. A future scheduler must persist the exact payload before dispatch; persistence/dispatch is not implemented yet. Server activation still requires the explicit staging destination and server-only credential. No credentials were obtained or configured by this change.

Publication transport errors are now treated as uncertain: the request might have committed before the response was lost. The runner must not claim no changes occurred. The database replay contract can resolve the same run/payload safely. Expiry has a separate retry function, so an expiry failure does not require rediscovery or a new publication. Missing/malformed publication or expiry results are failures, not successes.

Added isolated source verification helpers. Only reviewed Arbeitnow/Remotive HTTPS hosts are probed. Credentials, custom ports, arbitrary employer hosts and private/IP destinations are refused; redirects must remain in the reviewed host registry, with a bounded redirect count and request timeout. HEAD falls back to GET for 405 and cancels the response body. Two missing-source observations are needed to recommend expiry; rate limits, other temporary failures and skipped hosts never recommend expiry. These helpers are not wired to production or a scheduled database lifecycle worker yet.

Validation: TypeScript and sixteen member tests passed. New tests cover uncertain publication, rejected publication, separately retried expiry, blocked private addresses, unsafe redirects, confirmed 404 and transient 429 handling. Network/database calls in these new failure tests use controlled fakes; this is not evidence of a live authenticated runner integration.

No database changes, persistent pipeline run, external source probe, real-record import, recurring job or deployment occurred in this slice. Next is secure staging credential setup, persistent prepared-batch handling and controlled provider-to-database integration, followed by source-verification persistence and scheduling. The public opportunity feed still contains staging samples until a real-feed publication is explicitly activated.
